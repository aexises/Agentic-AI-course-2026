# First-learner pilot

The first learner is the course owner, with Python/ML experience and a need for backend/deployment practice. Use the [6–8-hour weekly route](SELF-STUDY-GUIDE.md). No student timing or learning-outcome measurements have yet been collected for this revision.

Before each lab, select the matching environment and confirm setup. Labs 3–5 are unsolved assignments; the three new engineering labs use guided TODOs in submission.py. Keep instructor solutions closed until an honest attempt and staged hints have been recorded.

Record reading, setup, implementation and debugging time separately. Include unfinished work, the first blocker, help used, tests added and a short explanation from memory. Classify blockers as environment, prerequisite, unclear instruction, implementation, or ambiguous test. A passing software suite is not proof of pedagogical effectiveness.

After each week, decide whether to split the next week or add a focused prerequisite rehearsal. Before revising duration estimates, retain the old estimate and actual observation. With one learner, report individual observations rather than claims about typical students. Use the [submission template](SUBMISSION-TEMPLATE.md) and [capstone rubric](CAPSTONE.md).
